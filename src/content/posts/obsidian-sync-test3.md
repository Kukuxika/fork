# Marcus 博客 V1.1 优化任务

项目路径：D:\buildwed\fork

技术环境：

- Astro + Firefly
    
- Obsidian 编辑 Markdown
    
- Obsidian Git 自动同步
    
- GitHub master 分支
    
- Cloudflare Pages 自动部署
    

## 一、自动管理文章时间

目前网站已经支持：

- 置顶文章优先。
    
- 按 `updated ?? published` 降序。
    
- 首页显示最近更新日期。
    

但 Obsidian 创建的文章默认只有年月日，无法区分同一天内的发布和修改顺序。

需要实现：

1. 新建博客文章时，自动生成精确到秒的 `published`。
    
2. 实际修改文章内容时，自动更新 `updated`。
    
3. 普通打开笔记、Git 同步、网站重新构建，不应该改变修改时间。
    
4. `published` 创建后保持不变。
    
5. 时间统一采用明确时区的 ISO 8601 格式，例如：
    

`2026-11-01T15:30:25+08:00`

优先研究 Obsidian 原生功能或成熟插件能否实现时间自动维护，不要为了简单功能开发复杂系统。

特别注意：不能在 Astro 构建时统一生成当前时间，否则每次构建都可能让旧文章错误地变成最新文章。

## 二、完善文章排序

保持现有规则：

1. 置顶文章优先。
    
2. 非置顶文章按照 `updated ?? published` 的完整时间戳降序排列。
    
3. 时间相同时，使用稳定的次级排序规则。
    
4. 兼容以前只有 `YYYY-MM-DD` 的旧文章。
    
5. 首页、分页和上一篇/下一篇文章的顺序保持一致。
    

前端继续只显示日期，例如：

`最近更新于 2026-11-01`

不必显示时分秒。

## 三、提高文章构建稳定性

之前出现过两类错误：

- `tags:` 为空，导致 Astro 数据验证失败。
    
- Obsidian 创建空白 Markdown 文件，导致网站构建失败。
    

需要：

1. 将缺失或为 null 的 tags 规范化为空数组。
    
2. 检查其他常见的空属性是否存在类似问题。
    
3. 确保模板文件不会被识别为文章。
    
4. 提供安全的草稿目录，避免普通空白笔记被 Astro 当作文章。
    
5. 优先保留现有文章路径，不要大规模迁移文件。
    
6. 不要悄悄隐藏已发布文章的真实格式错误，应保留明确的验证提示。
    

## 四、优化 Obsidian 写作流程

希望最终实现：

新建文章 → 自动填写发布时间 → 编辑文章 → 自动更新修改时间 → Git 同步 → Cloudflare 部署 → 网站自动排序。

如果需要修改 Obsidian 插件配置，请提供明确的操作步骤。

不能影响当前正常运行的 Obsidian Git 自动同步功能。

注意：公开 GitHub 仓库中的草稿仍然可能被访问。草稿目录只用于隔离构建，不应被视为隐私保护措施。

## 五、暂不开发浏览量

保留未来增加真实文章浏览量的计划。

本次不引入数据库、第三方统计后端或新付费服务。

## 六、测试与验收

请至少测试：

1. 同一天发布三篇文章，按照发布时间正确排序。
    
2. 修改最早发布的文章，更新时间后自动排到前面。
    
3. 不修改文章内容时，更新时间保持不变。
    
4. 没有 updated 的文章正常排序。
    
5. tags 为空时构建成功。
    
6. 草稿目录中的空白 Markdown 不参与构建。
    
7. 旧文章、图片、分类、标签和文章链接保持正常。
    
8. pnpm check、pnpm build 等项目适用的检查通过。
    

请先检查现有实现，优先复用已有代码。

修改完成后报告变更文件和测试结果，暂时不要自动提交或推送 GitHub。
